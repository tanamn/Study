# 1. 문서 목적

요구사항을 실제 업무 처리 절차와 검증 규칙으로 구체화한다. 구현 전에
업무 흐름과 예외 상황을 정의하여 계좌 잔액 및 거래내역의 정합성을
확보한다.

## 2. 업무 기능 구성

| 업무 | 주요 처리 |
|---|---|
| 계좌 조회 | 계좌 존재 여부 확인 후 기본정보와 잔액 반환 |
| 입금 | 계좌 상태 확인, 잔액 증가, 거래내역 기록 |
| 출금 | 계좌 상태 및 잔액 확인, 잔액 차감, 거래내역 기록 |
| 계좌이체 | 양 계좌 검증, 출금, 입금, 거래내역 기록 |
| 거래내역 조회 | 계좌 및 조회 조건에 따른 거래 목록 반환 |

## 3. 입금 업무

### 3.1 처리 절차

1.  요청 계좌번호와 입금 금액을 검증한다.
2.  계좌가 존재하고 거래 가능한 상태인지 확인한다.
3.  입금 금액이 유효한지 확인한다.
4.  계좌 잔액을 증가시킨다.
5.  입금 거래내역을 기록한다.
6.  처리 결과를 반환한다.

### 3.2 예외 상황

-   계좌번호가 존재하지 않음
-   거래 정지 계좌
-   금액이 0 이하
-   잔액 갱신 또는 거래내역 저장 실패

## 4. 출금 업무

### 4.1 처리 절차

1.  계좌번호와 출금 금액을 검증한다.
2.  계좌의 거래 가능 상태를 확인한다.
3.  출금 가능 잔액을 확인한다.
4.  잔액을 차감한다.
5.  출금 거래내역을 기록한다.
6.  처리 결과를 반환한다.

### 4.2 핵심 설계 사항

잔액 확인과 차감 사이에 다른 거래가 개입할 수 있으므로 단순 조회 후
차감만으로는 동시성 문제가 발생할 수 있다. 조건부 UPDATE 또는 비관적
잠금 등 제어 방식을 선택하고 검증한다.

## 5. 계좌이체 업무

### 5.1 처리 절차

1.  출금 계좌와 입금 계좌 및 이체 금액을 검증한다.
2.  두 계좌의 존재 여부와 거래 가능 상태를 확인한다.
3.  출금 계좌의 잔액을 확인한다.
4.  출금 계좌 잔액을 차감한다.
5.  입금 계좌 잔액을 증가시킨다.
6.  출금 및 입금 거래내역을 기록한다.
7.  모든 작업이 성공하면 커밋한다.

### 5.2 트랜잭션 원칙

출금, 입금, 거래내역 기록은 하나의 트랜잭션으로 처리한다. 중간 단계에서
오류가 발생하면 전체 작업을 롤백한다.

### 5.3 이체 흐름

``` text
이체 요청
  |
요청값 및 계좌 검증
  |
출금 가능 여부 확인
  |
출금 계좌 차감
  |
입금 계좌 증가
  |
거래내역 기록
  |
전체 성공?
  | 예                 | 아니오
 COMMIT              ROLLBACK
```

## 6. 거래내역 설계 원칙

-   거래를 식별할 수 있는 고유 거래 ID를 부여한다.
-   거래유형(입금, 출금, 이체)을 구분한다.
-   거래 금액, 거래 전후 잔액, 처리 시각 및 상태를 기록한다.
-   이체는 하나의 이체 식별자로 출금·입금 내역을 연관시킨다.
-   거래내역은 사후 추적이 가능하도록 임의 수정·삭제를 제한하는 방향으로
    설계한다.

## 7. 상태 및 오류 처리

업무 오류와 시스템 오류를 구분한다. 잔액 부족, 계좌 상태 오류 등은 업무
오류로 처리하고, 데이터베이스 연결 실패 등은 시스템 오류로 처리한다.

## 8. 설계 검토 항목

-   모든 업무 규칙이 요구사항과 일치하는가?
-   이체 실패 시 출금만 반영되는 상황을 방지하는가?
-   동시 거래에서 잔액이 음수가 되지 않는가?
-   거래내역으로 거래 결과를 추적할 수 있는가?
-   중복 요청을 어떻게 식별하고 처리할 것인가?
