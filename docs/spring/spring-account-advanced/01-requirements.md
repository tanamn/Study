# Spring 계좌관리 심화 과정 - 1단계.업무 요구사항

## 1. 문서 목적

계좌관리 심화 프로젝트에서 구현할 금융 업무의 범위와 기능·비기능
요구사항을 정의한다. 이 문서는 이후 업무 설계, 데이터베이스 설계, API
설계 및 테스트의 기준으로 사용한다.

## 2. 업무 범위

### 2.1 포함 범위

-   계좌 기본정보 조회
-   계좌 잔액 조회
-   입금 처리
-   출금 처리
-   계좌 간 이체
-   거래내역 조회
-   거래 실패 및 오류 처리
-   트랜잭션과 동시성 제어
-   기본 인증·인가 및 테스트

### 2.2 제외 또는 후속 확장 범위

-   실제 은행·증권사의 외부 전문 연계
-   실계좌 및 실제 자금 이동
-   대외 결제망 연계
-   실명확인 및 법적 고객확인 절차
-   운영 수준의 보안 인증과 규제 준수 검증

본 프로젝트는 학습용 모의 금융 시스템이며 실제 금융 거래에 사용하지
않는다.

## 3. 사용자 및 업무 주체

| 주체 | 역할 |
|---|---|
| 고객 | 본인 계좌 조회 및 거래 요청 |
| 관리자 | 학습용 데이터 및 계좌 상태 관리 |
| 시스템 | 거래 검증, 잔액 변경, 거래내역 기록 |

## 4. 기능 요구사항

| ID | 기능 | 요구사항 |
|---|---|---|
| FR-001 | 계좌 조회 | 계좌번호로 계좌 기본정보와 잔액을 조회한다. |
| FR-002 | 입금 | 유효한 계좌에 입금액을 반영하고 거래내역을 기록한다. |
| FR-003 | 출금 | 계좌 상태와 잔액을 확인한 후 출금한다. |
| FR-004 | 계좌이체 | 출금 계좌와 입금 계좌를 검증하고 이체를 처리한다. |
| FR-005 | 거래내역 | 계좌별 거래내역을 기간 및 거래유형으로 조회한다. |
| FR-006 | 거래 검증 | 금액, 계좌 상태, 잔액 등 업무 규칙을 검증한다. |
| FR-007 | 오류 처리 | 거래 실패 사유를 일관된 오류 응답으로 반환한다. |
| FR-008 | 인증·인가 | 사용자와 권한에 따라 API 접근을 제한한다. |

## 5. 주요 업무 규칙

-   거래 금액은 0보다 커야 한다.
-   출금 및 이체는 출금 가능 잔액을 초과할 수 없다.
-   거래 대상 계좌는 존재하고 거래 가능한 상태여야 한다.
-   동일 계좌 간 이체는 허용하지 않는다.
-   이체의 출금·입금·거래내역 기록은 하나의 논리적 거래로 처리한다.
-   거래 처리 중 일부 작업이 실패하면 전체 거래를 취소해야 한다.
-   잔액 변경과 거래내역 기록의 정합성을 유지해야 한다.
-   중복 요청에 대한 처리 정책은 별도로 정의하고 테스트한다.

## 6. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 데이터 정합성 | 잔액과 거래내역 간 불일치가 발생하지 않아야 한다. |
| 보안 | 입력값 검증, SQL 파라미터 바인딩, 인증·인가를 적용한다. |
| 유지보수성 | Controller, Service, Mapper의 책임을 분리한다. |
| 테스트 가능성 | 정상·오류·경계·동시성 상황을 재현할 수 있어야 한다. |
| 추적성 | 거래 식별자와 처리 결과를 확인할 수 있어야 한다. |

## 7. 예외 상황 목록

-   존재하지 않는 계좌
-   거래 정지 계좌
-   0 또는 음수 금액
-   잔액 부족
-   출금 계좌와 입금 계좌가 동일한 경우
-   데이터베이스 오류
-   거래 중 일부 SQL 실행 실패
-   동시에 동일 계좌에서 출금 요청이 발생한 경우
-   동일 요청이 반복 전달되는 경우

## 8. 요구사항 추적

각 요구사항은 업무 설계, API, 구현 코드 및 테스트 케이스와 연결한다.
구현 과정에서 요구사항이 변경되면 관련 문서와 테스트도 함께 갱신한다.
