# 1. 문서 목적

계좌관리 기능이 요구사항과 업무 규칙에 맞게 동작하는지 검증한다. 정상
흐름뿐 아니라 입력 오류, 업무 오류, 트랜잭션 롤백 및 동시성 상황을
확인한다.

## 2. 테스트 범위

| 테스트 유형 | 검증 대상 |
|---|---|
| 단위 테스트 | Service 업무 규칙, 검증 및 예외 |
| Mapper 테스트 | SQL 실행과 결과 매핑 |
| 통합 테스트 | Controller부터 DB까지 전체 흐름 |
| API 테스트 | HTTP 요청·응답 및 상태 코드 |
| 트랜잭션 테스트 | 실패 시 전체 롤백 |
| 동시성 테스트 | 동시에 발생한 거래의 잔액 정합성 |

## 3. 기능별 테스트 시나리오

### 3.1 계좌 조회

-   존재하는 계좌 조회 성공
-   존재하지 않는 계좌 조회
-   거래 정지 계좌 조회 정책 확인

### 3.2 입금

-   정상 금액 입금
-   0원 및 음수 금액 거부
-   존재하지 않는 계좌 입금 거부
-   잔액과 거래내역 동시 반영 확인

### 3.3 출금

-   잔액 이내 출금 성공
-   잔액 초과 출금 거부
-   0원 및 음수 금액 거부
-   거래 정지 계좌 출금 거부

### 3.4 계좌이체

-   정상 이체
-   잔액 부족
-   출금 계좌 또는 입금 계좌 없음
-   동일 계좌 간 이체
-   입금 단계 실패 시 출금도 롤백되는지 확인
-   거래내역이 양쪽 계좌에 올바르게 기록되는지 확인

## 4. 트랜잭션 테스트

이체 처리 중 입금 단계에서 예외가 발생하도록 테스트 조건을 만든다.

검증 항목:

-   출금 계좌 잔액이 원래 값으로 복구되는가?
-   입금 계좌 잔액이 변경되지 않는가?
-   출금 거래내역이 남지 않는가?
-   입금 거래내역이 남지 않는가?

테스트는 실제 트랜잭션이 적용되는 통합 테스트 환경에서 검증한다.

## 5. 동시성 테스트

동일 계좌에 여러 출금 요청을 동시에 발생시킨다.

예시:

-   시작 잔액: 100,000원
-   요청 A: 70,000원 출금
-   요청 B: 50,000원 출금

두 요청이 모두 성공하면 잔액이 음수가 되거나 데이터 정합성이 깨질 수
있다. 설계한 잠금 또는 조건부 UPDATE가 한 요청만 성공하도록 제어하는지
확인한다.

## 6. 테스트 도구

| 도구 | 용도 |
|---|---|
| JUnit 5 | 테스트 실행 및 검증 |
| Mockito | 의존 객체 모의화 |
| Spring Boot Test | 애플리케이션 통합 테스트 |
| MockMvc | Controller/API 테스트 |
| Postman | 수동 API 호출 및 확인 |
| Swagger UI | API 명세 및 호출 확인 |

## 7. 테스트 결과 기록 양식

| 항목 | 기록 내용 |
|---|---|
| 테스트 ID | TC-001 등 |
| 요구사항 ID | FR-001 등 |
| 테스트 시나리오 | 검증할 업무 상황 |
| 사전 조건 | 계좌 및 잔액 등 초기 데이터 |
| 입력값 | 요청 URI 및 JSON |
| 기대 결과 | 상태 코드, 잔액, 거래내역 |
| 실제 결과 | 실행 후 확인한 결과 |
| 판정 | 성공 / 실패 |
| 비고 | 결함 및 보완 내용 |

## 8. 최종 검증 체크리스트

-   모든 기능 요구사항에 테스트가 연결되어 있는가?
-   금액과 계좌 상태의 경계값을 확인했는가?
-   잔액과 거래내역이 일치하는가?
-   이체 실패 시 전체 롤백되는가?
-   동시 요청에서 잔액 정합성이 유지되는가?
-   오류 응답에 내부 구현 정보가 노출되지 않는가?
-   테스트 결과와 미해결 결함을 기록했는가?

## 9. 완료 기준

핵심 기능의 정상·오류 테스트가 통과하고, 계좌이체의 원자성 및 동시성
검증 결과가 문서화되어야 한다. 미해결 항목은 별도 결함 목록으로
관리한다.
